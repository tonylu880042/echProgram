三、idea.txt 與目前 App 的差異（只記錄，不修改程式）
------------------------------------------------------------
idea.txt 提出 22 個 Program／體驗；目前 App library 實作上只有 8 個項目：
- Hero：FAT_BURN、GLUTE_BLAST、VERTICAL、SURPRISE_ME。
- Supporting：EASY_STROLL、SPEED_DEMON、ROLLING_HILLS、HEART_HEALTH。
目前 detail catalog 只提供 FAT_BURN；其餘可見項目會進入 unavailable。`MainActivity` 仍以 `NoOpWorkoutSessionStarter` 接線，因此 Start 只證明 setup／validated boundary，沒有真正 workout session。
Gate3A 已具備 FitOS 唯讀 telemetry boundary，但尚未具備 Gate3B 的 speed／incline control、command ACK、pause／resume、安全 stop 與真實 session reconciliation。HR、history／persistence、generator 亦尚未實作。
本次 txt 不會假裝上述差異已被程式修正；下一個程式增量應先以這些規格建立單一 ProgramDefinition source 與 completeness tests。

四、跨 Program 共同客戶決策
------------------------------------------------------------
1. 單位：UI 預設 MPH 還是 KM/H？速度／距離／history 比較是否固定保存 canonical unit？
2. 機台能力：每個 launch model 的最大 speed／incline、step、ramp rate、是否支援 0% 與 15%+。
3. 命名：FAT BURN、BOOTY BURN、12-3-30、VERTICAL MILE、RECOVERY 等名稱與對外文案的法務／行銷核准。
4. AIDL 控制：start／stop／speed／incline 的 ACK、timeout、拒絕原因、pause／resume、Binder death、host restart、safety key 與 app crash 行為。
5. HR：支援 Apple Watch／哪些 HR monitor、target zone 的權威來源、HR LOST timeout、hysteresis 與控制權限。
6. 估算 calories／elevation：資料來源、公式、confidence、rounding、`ESTIMATED` caveat、是否可由 FitOS authority 回報。
7. 資料持久化：profile、user cap、manual override、Adapt preference、history、PR、generator seed／version 與隱私／刪除政策。
8. Safety／UX：無裝置、stale、clamp、控制失敗、使用者按 stop 的共同 UI 文案與 default safe behavior。

五、建議確認順序與 MVP 分組
------------------------------------------------------------
第一批：先確認單位、機台 caps／limits、共用 safety／preview 文案。以唯讀／static profile 完成 FAT BURN、GLUTE BLAST、POWER WALK、ROLLING HILLS、RECOVERY WALK、QUICK 10、SWEAT 30、PYRAMID、SUMMIT、BOOTY BURN 15、HIIT 20、SPEED LAB、WALK + RUN、ENDURANCE、ECHELON HYBRID RUN 的 detail／profile preview。
第二批：在 control contract 核准後，接入固定 profile 的 session engine；先做 countdown、NEXT、manual override、stale／clamp，不直接啟用未驗證的 automatic control。
第三批：確認 HR contract 後做 ZONE 2；確認 elevation authority／formula 後做 VERTICAL；確認 calories estimator／time limit 後做 CALORIE TARGET。
第四批：有足夠 history 後做 ECHELON CHALLENGE；有 baseline／週期決策後做 5K READY progression；有 deterministic generator contract 後做 SURPRISE ME。
第五批：完成 persistence、結果頁、比較／PR 的證據規則與客戶／法務文字，再決定哪些 Program 可開放真實 device control。

七、非功能與實作提醒
------------------------------------------------------------
- 本次文件不是測試替代品；程式實作仍須遵守 AGENTS.md 的 RED -> GREEN -> REFACTOR。
- Gate3A 只證明可讀 telemetry／stale／connection boundary；不能宣稱真實 device control。
- 任何 `EFFORT +/-`、Adapt、目標 generator、HR 自動調整都必須先有 application port、fake／boundary test 與 safe fallback。
- 不新增 emoji 作為 UI icon；UI 可保留正式英文 Program 名稱與 coaching 文案，但圖示需使用核准 icon set。
